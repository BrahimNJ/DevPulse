# 0013. Show repository activity from GitHub's repository statistics

- Status: accepted
- Date: 2026-11-01

## Context

The branch report (ADR 0005) shows the state of a repository and delivery health
(ADR 0010) how its pull requests reach main. Neither says how a repository moves over
time or who keeps it running: whether it speeds up or winds down, when its people
commit, and whether it depends on one or two maintainers. The landing page listed the
commit heatmap, activity trends, bus factor and new versus returning contributors as
planned (#68). The site runs on a free tier with a daily allowance per visitor
(ADR 0008), so the feature must stay cheap in GitHub API points.

## Decision

- **Data:** three REST statistics GitHub computes for every repository, read in
  parallel, 1 core point each: `stats/commit_activity` (commits per day over 52
  weeks), `stats/contributors` (the most active contributors with their weekly
  commits over the whole history) and `stats/punch_card` (commits by day and hour, in
  the time zone of each commit). They count commits on the default branch without
  merge commits.
- **Statistics being computed:** GitHub answers 202 while it computes a statistic. Each
  pending one is asked again twice, after 3 and 5 seconds; if it is still pending, the
  API answers 503 with `retry-after: 10` and the `statistics-pending` code, the visitor
  is not charged, and nothing is cached. The interface retries once by itself, then
  offers a button. A 204 (no commits) is an empty report, not an error.
- **Metrics, computed by the domain layer** (`src/activity/report.ts`) from plain data
  and an injected clock:
  - a rule-based verdict per window of 3, 6 or 12 months: dormant without a commit,
    quiet under one a week, otherwise growing or slowing when the second half of the
    window differs from the first by 30 % or more, steady in between. The week in
    progress is drawn but left out of every average;
  - weekly commits with the median of the eight complete weeks ending with each one;
  - concentration: the fewest people, bots excluded, whose commits reach half of the
    total, over the window and over all time;
  - contributor flow over four blocks of 13 weeks: new, retained, returning, lapsed;
  - rhythm from the punch card: weekend share, weekday office-hours share, peak hour;
  - maintenance signals: the week of the latest human commit, the bot share, and the
    share of commits attributed to listed contributors.
- **Bots** are accounts of type `Bot` or names ending in `[bot]`.
- **No ranking of people:** contributor names appear only in the concentration bar.
  Commit counts do not measure the value of anyone's work; a leaderboard would invite
  that reading.
- **Release markers** come from the delivery report, which now returns the dates of the
  stable releases it reads (`releases.recent`), rather than a fourth request.
- **API:** `GET /api/activity?repo=owner/name`, cached for 10 minutes like the other
  reports and sharing the visitor's daily allowance. No CLI command, like delivery.
- **Interface:** a third Activity tab. One window selector drives every chart except the
  punch card, whose period GitHub decides. Selecting a week in the trend (by mouse or
  keyboard) or in the calendar opens its detail. Panels are numbered in reading order
  and each states how to read it and what it cannot see. Charts are hand-written SVG on
  the tokens of ADR 0012. Before a first analysis the tab shows an illustrative example
  shaped on nodejs/node, generated by the same rules so its figures agree.

## Alternatives considered

- **Commit history through GraphQL, page by page.** Exact authors and dates, but a busy
  repository needs dozens of requests for a year, beyond what the allowance and the free
  tier allow.
- **Computing statistics client-side from the raw weekly data.** Moves the rules into the
  browser, where they cannot be tested with the domain, and sends hundreds of kilobytes
  of contributor history for large repositories.
- **Waiting until GitHub finishes computing.** It can take minutes for a large
  repository; holding the request would hit the 30-second timeout and keep an instance
  busy.
- **A top-contributors leaderboard.** Rejected for the reason above; the catalogue keeps
  it as planned only as a proposal.

## Consequences

- Activity adds 3 GitHub points to each analysis, against 5,000 an hour.
- People outside the contributors GitHub lists (100, or 500 on some very large
  repositories, as measured on expressjs/express and nodejs/node) are invisible in the people figures; the
  interface says so when the list is full, and shows the share of commits it covers.
- Commits are only one kind of work: reviews, issues and releases do not count, and the
  panels say so.
- The punch card does not follow the window, and its hours are local to each commit.
- The first analysis of a rarely viewed repository may need a retry while GitHub
  computes its statistics.
- Extends ADRs 0006, 0008 and 0010.
